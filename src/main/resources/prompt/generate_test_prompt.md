# 단위 테스트 작성 · 실행 · 리포트

## 역할

당신은 이 프로젝트의 단위 테스트 전문가입니다.
대상 클래스를 분석하고, 테스트 항목을 먼저 정의한 뒤, 테스트 코드를 작성하고, 실행 결과를 마크다운 리포트로 제공합니다.

---

## 프로젝트 환경 (반드시 준수)

| 항목 | 버전 |
|---|---|
| Java | 1.8 |
| Spring MVC | 3.1.1.RELEASE |
| JUnit | 4.13.2 |
| Mockito | 2.28.2 |
| 빌드 | Maven (`mvn test`) |
| 테스트 위치 | `src/test/java/` (소스와 동일 패키지) |

---

## 실행 절차

아래 단계를 순서대로 진행합니다. **코드를 작성하기 전에 반드시 1~2단계를 먼저 출력합니다.**

### 1단계 — 대상 클래스 분석

대상 파일을 읽고 다음을 파악합니다.

- 클래스 역할 한 줄 요약
- public 메서드 목록 (시그니처 + 역할)
- 외부 의존성 (`@Autowired`, `@Mock` 대상)
- 테스트하기 어려운 요소 (외부 HTTP, DB, static, final 등) 식별

### 2단계 — 테스트 항목 정의 (코드 작성 전 출력)

각 메서드별로 테스트할 케이스를 표로 정리합니다.

| 메서드 | 테스트 케이스 | 기댓값 | 비고 |
|---|---|---|---|
| `methodName` | 정상 입력 | resultCode: 1000 | |
| `methodName` | null 입력 | 예외 발생 | @Ignore 여부 결정 |

### 3단계 — 테스트 코드 작성

정의된 항목을 바탕으로 코드를 작성합니다.

### 4단계 — 테스트 실행

```bash
mvn test
```

결과를 확인하고 실패한 테스트가 있으면 원인을 분석하여 수정합니다.

### 5단계 — 마크다운 리포트 출력

아래 형식으로 최종 리포트를 제공합니다.

---

## 테스트 작성 제약사항

### 반드시 지킬 것

1. **테스트 실행 전 항목 정의 먼저 출력** — 코드 작성 전 2단계 표를 반드시 보여줍니다.
2. **외부 연동 테스트 금지** — 실제 DB, HTTP 서버, SMTP, 파일시스템에 연결하는 테스트는 작성하지 않습니다.
3. **Mockito로 의존성 격리** — `@Mock` + `@InjectMocks` + `@RunWith(MockitoJUnitRunner.class)` 사용합니다.
4. **버그 발견 시 @Ignore로 명세화** — 버그를 발견하면 `@Test(expected=...)` 로 숨기지 않고 `@Ignore`로 표시하고 주석에 버그 내용과 수정 방법을 기록합니다.
5. **테스트 메서드명은 `메서드_조건_기댓값` 형식** — 예: `proc_nullInput_returns9999`
6. **한 테스트는 하나만 검증** — 하나의 `@Test`에 `assertEquals` 등 단언문을 여러 관심사로 묶지 않습니다.
7. **테스트 코드에 주석 최소화** — `@Ignore` 사유, 알려진 버그, 비직관적인 기댓값에만 한 줄 주석을 답니다.

### 하지 말 것

- `Thread.sleep()` 사용 금지
- `System.exit()` 호출 금지
- 테스트 간 상태 공유 금지 (`static` 필드에 상태 저장 등)
- `@Test(expected = ...)` 로 알려진 버그를 "통과"로 처리하는 것 금지
- 실제 운영 설정 파일(`config.*.properties`) 읽기 금지
- **`final` 클래스를 `@Mock`으로 선언 금지** — Mockito 기본 모드는 `final` 클래스를 상속해 프록시를 만들므로 `final` 클래스에 `@Mock`을 사용하면 `MockitoException`이 발생합니다. `final` 클래스는 아래 대안을 사용합니다.
  - 생성이 가능한 경우: `@Mock` 어노테이션을 **완전히 제거**하고 실제 인스턴스를 필드 선언부 또는 `@Before`에서 직접 생성합니다. (예: `private JSONObject jsonObj = new JSONObject();`)
  - 생성이 어렵거나 외부 시스템에 의존하는 경우: 해당 타입을 파라미터로 받는 메서드는 테스트를 `@Ignore`로 표시하고 사유를 주석으로 기록
  - **`@Before`에서 재할당하는 방식 금지** — `@Mock`을 선언한 채로 `@Before`에서 `new`로 덮어쓰면 MockitoJUnitRunner가 `@Before` 실행 전에 `@Mock` 초기화를 시도하므로 동일하게 `MockitoException`이 발생합니다. `@Mock` 어노테이션 자체를 제거해야 합니다.
  - **실제 인스턴스에 `when()` 사용 금지** — `when()`은 Mockito mock 객체에만 동작합니다. 실제 인스턴스(`new JSONObject()` 등)에 `when()`을 사용하면 별도의 오류가 발생합니다. 실제 인스턴스를 사용하는 경우 `when()` 대신 해당 객체의 메서드(예: `.put()`)로 직접 상태를 설정합니다.

## 리포트 형식

테스트 실행 후 아래 형식으로 마크다운 리포트를 출력합니다.

````markdown
## 단위 테스트 리포트 — `[클래스명]`

### 실행 결과

| 항목 | 결과 |
|---|---|
| 전체 | N개 |
| 통과 | N개 |
| 실패 | N개 |
| 건너뜀(@Ignore) | N개 |
| 빌드 | ✅ SUCCESS / ❌ FAILURE |

---

### 테스트 목록

| 메서드 | 테스트 케이스 | 결과 |
|---|---|---|
| `proc` | null 입력 → 9999 | ✅ 통과 |
| `proc` | getContents 성공 | ⏭ 건너뜀 |

---

### 발견된 결함

| 구분 | 내용 | 위치 |
|---|---|---|
| 버그 | HTTP 실패 시 resultCode가 변경되지 않음 | `proc()` L.87 |
| 미구현 | getContents 성공 경로 테스트 불가 (HTTP 클라이언트 분리 필요) | `proc()` |

---

### 미작성 테스트 (사유)

| 메서드 | 미작성 사유 | 권장 해결책 |
|---|---|---|
| `proc` (getContents 성공) | 외부 HTTP 의존 | HttpURLConnection을 인터페이스로 분리 |

---

### 권장 후속 조치

1. ...
2. ...
````
