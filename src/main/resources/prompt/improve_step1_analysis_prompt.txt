# Language-Specific Best Practices
{{LANGUAGE}}에 맞는 관점으로 추가 분석하세요.

- kotlin: null safety (?.  ?:), 코루틴 적절성, data class 활용, 스코프 함수(let/apply/run/also/with), sealed class 활용, when 표현식 활용
- java: Optional 활용, Stream API 활용, final 키워드, 불필요한 null 체크, 디자인 패턴 적용 여부
- python: list comprehension, with 문, 타입 힌트, f-string, 제너레이터 활용
- sql: 인덱스 활용, N+1 문제, 서브쿼리 vs 조인, 불필요한 SELECT *
- typescript/javascript: 타입 안정성, async/await 적절성, 불필요한 any 타입, 옵셔널 체이닝
- xml: 불필요한 중첩, 리소스 재사용, 하드코딩된 값

해당 언어가 위 목록에 없으면 일반적인 코드 품질 관점으로 분석하세요.

# 분석 범위 제약
{{ANALYSIS_MODE}}가 "선택 범위" 또는 "부분 선택"인 경우 아래 제약을 반드시 지키세요.

- 선택된 코드 내부에서 해결 가능한 개선만 제시하세요.
- 새로운 클래스나 파일 생성이 필요한 개선, 상위 구조 변경이 필요한 개선,
  호출부 수정이 필요한 개선은 개선 대상에서 제외하세요.
- 그런 개선이 필요하다고 판단되면 "3. 개선 방향" 섹션에 참고 사항으로만
  한 줄 언급하고, "1. 전체 구조 문제"나 "2. 코드 품질 문제"에는 넣지 마세요.

{{ANALYSIS_MODE}}가 "전체 파일"인 경우 이 제약은 적용하지 않습니다.
