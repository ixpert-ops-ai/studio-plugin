## ⚠️ 분석 시 주의 및 금지 사항 (반드시 준수)
1. **호출 방향 주의**: 위 `[상위 호출처 트리]`는 이 대상을 '호출하는 쪽(Caller)'을 추적한 것입니다. 대상 메서드가 호출하는 하위 의존성(Callee)이 아님을 절대 혼동하지 마세요.
2. **신뢰도 구분**: 트리에 `[텍스트폴백]` 태그가 붙은 항목은 구문 분석이 아닌 단순 문자열 검색으로 추정된 결과입니다. 실제 호출이 아닐 수 있으므로 영향도 판단 시 "확인 필요"라고 명시하세요.
3. **추측 금지**: 트리에 없는 파일이나 메서드를 상상해서 영향 목록에 포함하지 마세요. 확인된 사실(PSI)과 추정(텍스트폴백)을 명확히 분리하세요.
4. **미탐색 영역**: 외부 라이브러리(Android SDK 내부, Kotlin 표준 라이브러리 등) 및 리플렉션 기반 호출은 추적되지 않았으므로 섣불리 분석하지 마세요.

## 🛠 Android 분석 시나리오별 영향 판단 기준
- **시그니처 변경** (파라미터/반환타입 변경, 이름 변경): 모든 호출처가 직접 영향을 받으며 즉각적인 컴파일 에러가 발생함.
- **내부 로직 변경** (시그니처 유지): 반환값의 의미나 상태가 바뀌는 경우에 한해 호출처에 간접 영향을 줌.
- **ViewModel 변경**: 해당 ViewModel을 observe/collect하는 Fragment/Activity/Composable 전체 영향.
- **Repository/DataSource 변경**: 해당 Repository를 주입받는 ViewModel/UseCase 전체 영향.
- **Room DAO 변경**: 해당 DAO를 사용하는 Repository 및 상위 레이어 전체 영향.
- **Composable 변경**: 해당 Composable을 호출하는 상위 Composable 및 Screen 전체 영향.
- **Coroutine Flow 변경**: collect/collectAsState로 구독하는 모든 호출처 영향.
- **메서드/클래스 삭제**: 모든 호출처에서 치명적인 컴파일/런타임 에러 발생.
위 기준을 적용하여 분석 대상 코드의 성격에 맞는 예상 시나리오를 가이드하세요.
