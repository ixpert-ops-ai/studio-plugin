# Android Best Practices
아래 Android 개발 관점으로 분석하세요.

- Architecture: ViewModel/Repository 패턴 준수, UI 로직과 비즈니스 로직 분리
- Lifecycle: lifecycleScope/viewLifecycleOwner 적절 사용, 메모리 누수 가능성
- Coroutine: suspend 함수 적절성, Dispatcher 선택 (IO/Main/Default), 취소 처리
- Compose: Recomposition 최소화, State 관리 (remember/rememberSaveable), SideEffect 적절성
- Room: DAO 패턴, suspend/Flow 활용, 인덱스 설정
- Hilt: 주입 범위 적절성 (Singleton/ActivityScoped 등)
- null safety: ?. ?: let 활용, 불필요한 !! 사용 제거
- 리소스: 하드코딩된 문자열/색상/크기 제거, strings.xml/dimens.xml 활용

# Android 버전 및 SDK 대응 관점
아래 관점도 함께 분석하되, 코드에서 실제로 사용 중인 API에 한해서만 언급하세요.

- targetSdk / compileSdk 상향 시 영향받는 API 사용 여부
- Deprecated 되었거나 동작이 변경된 API 사용 여부
  (Scoped Storage, 백그라운드 위치, 알림 권한,
   PendingIntent mutability, foreground service type 등)
- 런타임 권한 요구가 추가된 API 사용 여부
- 최신 권장 대체 API가 존재하는 경우 함께 안내

프로젝트의 현재 SDK 수준은 알 수 없으므로,
"targetSdk N 이상에서는 ~" 형태로 조건을 명시하여 서술하세요.

# 분석 범위 제약
{{ANALYSIS_MODE}}가 "선택 범위" 또는 "부분 선택"인 경우 아래 제약을 반드시 지키세요.

- 선택된 코드 내부에서 해결 가능한 개선만 제시하세요.
- 새로운 클래스나 파일 생성이 필요한 개선, 상위 구조 변경이 필요한 개선,
  호출부 수정이 필요한 개선은 개선 대상에서 제외하세요.
- 그런 개선이 필요하다고 판단되면 "3. 개선 방향" 섹션에 참고 사항으로만
  한 줄 언급하고, "1. 전체 구조 문제"나 "2. 코드 품질 문제"에는 넣지 마세요.
