Explain This Code

선택한 코드 블록의 역할, 동작 흐름, 주요 로직을 자연어로 설명합니다.

단일 스텝
✅

Review This Code

코드 품질·버그·보안 이슈를 리뷰하고, 개선된 코드를 SEARCH/REPLACE 형식으로 제안합니다.

2단계 파이프라인
⚡

Improve This Code

분석 → 코드 개선 → 안정성 평가 3단계로 리팩토링을 수행합니다. 3-way diff로 변경 내용을 시각화합니다.

3단계 파이프라인
🌊

Impact Analysis

선택한 코드 변경이 프로젝트 전반에 미치는 영향 범위를 분석합니다.

🗄️

Query Validation

📄

action/

IDE 이벤트 수신 및 WebviewActionRouter 라우팅. 비즈니스 로직 없이 Agent를 호출하는 역할만 수행합니다.

로직 추가 금지
agent/

TaskAgent가 IntentAnalyzer → TaskPipeline → AgentStep 순서로 LLM을 호출하고 결과를 조합합니다.

직접 파일 수정 금지
service/

EditorContextService, EditorApplyService, FileSearchService 등 IDE API 래퍼. Agent의 요청을 실행합니다.

LLM 호출 금지
client/

LLMClient 인터페이스 → OllamaClient / OpenAIClient 구현. SettingsState에서 baseUrl·model·timeout을 읽습니다.

Agent 에서만 사용
prompt/

PromptManager가 resources/prompt/*.txt를 로드. 프롬프트는 코드 내 하드코딩 금지, 기능별로 파일 분리.

하드코딩 금지
ui/bridge/

JcefBridge(IDE→JS)와 JcefMessageHandler(JS→IDE)가 단방향 메시지 채널을 구성합니다. GC 방지를 위해 강한 참조 유지.

Phase 2

요구사항 기반 자동 코드 생성

MetaGraph로 프로젝트 전체를 분석한 뒤, 자연어 요구사항만으로 대상 파일 선별부터 코드 작성, 단위 테스트까지 자동으로 수행합니다.

/metagraph

프로젝트 메타그래프 생성

Spring 엔드포인트, JPA 엔티티, Bean을 PSI로 파싱하여 project-graph.json을 생성합니다. 이후 모든 LLM 호출에 관련 그래프 컨텍스트가 자동 주입됩니다.

/analyze

요구사항 분석 (RequirementAnalysisPipeline)

자연어 요구사항을 입력하면 메타그래프에서 수정 대상 파일 목록(TargetFileSpec)을 추출합니다. 대형 프로젝트는 RelevanceFilter로 관련 파일만 선별합니다.

/implement

자동 코드 수정 (ImplementationPipeline)

분석 결과를 바탕으로 Contract-First 순서(DTO/Entity → Interface → Impl → Controller)로 각 파일을 순차 수정합니다. SignatureValidator로 인터페이스 계약을 검증합니다.

/test-all

단위 테스트 일괄 생성 (TestGenerationPipeline)

수정된 파일 전체에 대해 단위 테스트를 자동 생성합니다. TestFileMapper가 기존 테스트 파일을 찾거나 새로 생성합니다.
