users.stream()
  .filter(u -> u.getRole() == Role.ADMIN)
  .sorted(Comparator.comparing(User::getName))
  .collect(Collectors.toList());
✅ AI 설명
이 코드는 사용자 목록에서 관리자(ADMIN) 역할을 가진 사용자만 필터링한 뒤, 이름 기준 오름차순으로 정렬하여 새 리스트로 반환합니다. Java Stream API의 filter → sorted → collect 파이프라인을 사용하며, 원본 컬렉션을 변경하지 않습니다.

엄격한 5계층 구조로 각 계층의 책임을 분리합니다. 계층 간 의존 방향은 단방향으로 고정됩니다.

action/

IDE 이벤트 수신 및 WebviewActionRouter 라우팅. 비즈니스 로직 없이 Agent를 호출하는 역할만 수행합니다.

로직 추가 금지
agent/

TaskAgent가 IntentAnalyzer → TaskPipeline → AgentStep 순서로 LLM을 호출하고 결과를 조합합니다.

직접 파일 수정 금지
service/

EditorContextService, EditorApplyService, FileSearchService 등 IDE API 래퍼. Agent의 요청을 실행합니다.

LLM 호출 금지
client/

LLMClient 인터페이스 → OllamaClient / OpenAIClient 구현. SettingsState에서 baseUrl·model·timeout을 읽습니다.

Agent 에서만 사용
prompt/

PromptManager가 resources/prompt/*.txt를 로드. 프롬프트는 코드 내 하드코딩 금지, 기능별로 파일 분리.

하드코딩 금지
ui/bridge/

JcefBridge(IDE→JS)와 JcefMessageHandler(JS→IDE)가 단방향 메시지 채널을 구성합니다. GC 방지를 위해 강한 참조 유지.

강한 참조 필수

TaskPipeline

3

안정성 평가

원본·개선 코드를 비교하여 위험도를 평가합니다. isStabilityStep

Phase 2

요구사항 기반 자동 코드 생성

MetaGraph로 프로젝트 전체를 분석한 뒤, 자연어 요구사항만으로 대상 파일 선별과 변경 지시서 생성을 3단계로 수행합니다.

/metagraph

프로젝트 메타그래프 생성

Spring 엔드포인트, JPA 엔티티, Bean을 PSI로 파싱하여 project-graph.json을 생성합니다. 이후 모든 LLM 호출에 관련 그래프 컨텍스트가 자동 주입됩니다.

/analyze

요구사항 분석 (RequirementAnalysisPipeline)

자연어 요구사항을 입력하면 메타그래프에서 수정 대상 파일 목록(TargetFileSpec)을 추출합니다. 대형 프로젝트는 RelevanceFilter로 관련 파일만 선별합니다.

/implement

변경 지시서 생성 (ImplementationPipeline)

분석 결과를 바탕으로 Contract-First 순서(DTO/Entity → Interface → Impl → Controller)로 각 파일의 변경 지시서(의사코드)를 생성합니다. 코드를 직접 수정하지 않으며, 개발자가 지시서를 검토 후 적용합니다.
